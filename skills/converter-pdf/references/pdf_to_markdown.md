# pdf → Markdown 変換リファレンス

PDF 文書を AI 駆動開発で扱いやすい Markdown へ変換するときの方針。
PDF の見た目や紙面レイアウトを再現するのではなく、文書に含まれる**情報の構造と内容**を Markdown で読みやすく表現することが目的。

## 出力要件

- 出力形式は Markdown（`.md`）
- 出力先は変換元ファイルと同じディレクトリ。ファイル名は `変換元ファイル名.md`（`XXXXX_XXXXX.pdf` → `XXXXX_XXXXX.md`）
- 表形式の情報は Markdown テーブルで表現する
- 箇条書き、注記、手順、説明文は Markdown として自然に読める形に整理する
- ページをまたぐ表や段落は、内容が自然につながるように結合して整理する
- 章・節・項目の構造が分かるように見出し（`#`, `##`, `###` …）を付ける
  - ドキュメントタイトルを `#` 見出しとする
  - 章レベルを `##`、節レベルを `###`、以降は階層に応じて深くする
- Markdown 見出しからリンク付き目次を作成する

## 変換手段

- 組み込みの `pdf` スキル（`Skill(pdf)`）を使う

## 変換ルール

- ヘッダー、フッター、ページ番号、コピーライト表記、機械的な繰り返し文言は、本文理解に不要なら出力しない
- 改ページの都合で分断された文や表は、意味がつながるように補正してよい
- 段組みレイアウトは紙面の並びではなく、意味が通る順序で読み解いて Markdown 化する
- 表は列見出し・行見出しの対応関係が崩れないように Markdown テーブル化する
- 図表タイトル、注記、凡例など、内容理解に必要なテキストは残す
- 図・作業フローなど Mermaid で表現できるものは Mermaid 記法を使う
- 装飾的なアイコン、背景、罫線、色、フォントサイズ、余白などの見た目情報は持ち込まない
- OCR が必要な PDF の場合は、読み取れた範囲を Markdown 化する
- OCR 結果が不明瞭な箇所は推測で補完しない。判読困難な文字列を無理に創作しない
- ただし、明らかな改行崩れや OCR 由来の軽微な誤りは、文脈上明白な範囲で自然に補正してよい
- 文書として意味のあるラベルや注記は失わない
- 備考、注釈、入力説明、注意書きなど、文書として意味のある文言は残す

## 整形方針

- PDF の紙面構成を模写するのではなく、内容として自然に読める Markdown 構造へ整理する
- 可読性を優先し、長大すぎる1つの表や不自然な改行を避ける
- ページごとに繰り返される同じ内容は重複させない
- セクションごとに意味のまとまりを保つ
- 箇条書き、手順、注意事項、前提条件、制約事項、入出力、例外事項などは区別できるよう整理する
- セルや図版の位置情報、座標、ページ上の並び順の説明は出力しない
- 日本語の自然な見出し名を用い、機械的に座標を出力しない

## 禁止事項

- PDF の見た目やレイアウト再現を目的とした記述
- 変換ルールそのものや、PDF/Markdown の操作説明の出力
- OCR や変換処理に関する言い訳や補足コメント
- 判読できない箇所の憶測補完
- 「以下は変換結果です」などの前置き
- 不要なコードブロックの使用
