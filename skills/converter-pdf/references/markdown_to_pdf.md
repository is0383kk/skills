# Markdown → pdf 変換リファレンス

編集済み Markdown を PDF に書き出すときの方針。
Markdown の論理構造（見出し階層・表・箇条書き・図）をそのまま素直に PDF に対応付ける。

## 出力要件

- 出力形式は `.pdf`
- 出力先は変換元 Markdown と同じディレクトリ。ファイル名は `XXXX.md` → `XXXX.pdf`
- 出力先がすでに存在する場合は上書き可否をユーザーに確認する

## 入力の確認

呼び出し時に以下を確認する。

- 変換対象の Markdown ファイル（または Markdown を含むフォルダ）
- フォーマット（テンプレート／CSS／テーマファイル）の指定有無
  - 指定がある場合: そのスタイルに従う
  - 指定がない場合: 標準的な日本語向けスタイル（見出し・本文・表・コードブロック）で出力する

## 変換手段

- 組み込みの `pdf` スキル（`Skill(pdf)`）を使う
- 内部実装は環境に応じて Markdown → HTML → PDF（例: Pandoc + wkhtmltopdf / weasyprint / md-to-pdf 等）の経路でよい
- 日本語が含まれることを前提に、日本語フォントが描画できる構成を選ぶ

## 変換ルール

- 見出し階層は PDF 上でも階層が分かるサイズ・スタイルに対応させる（`#` が最上位）
- Markdown の目次（リンク付き目次）は、PDF 上でも目次として残す。ページ内リンクが張れる方式が望ましい
- 表は PDF テーブルとして再現する。列幅は内容に応じて自動調整でよい
- 箇条書き、番号付きリストはそのまま再現する
- コードブロックは等幅フォントで枠付き表示
- インラインの `（要確認: ...）` 注記は本文中にそのまま残す
- Mermaid 記法の図は `mermaid-js/mermaid-cli`（`mmdc`）等で画像化（PNG/SVG）してから PDF に埋め込む
  - `mmdc -i input.mmd -o out.png` のように実行
  - 画像化に失敗する場合は、Mermaid のソースをコードブロックとして残し、変換できなかった旨を最終報告に明記する
- リンクは PDF 上でクリック可能なリンクとして残す（外部 URL／ファイル間リンク）

## 整形方針

- A4 縦を基本ページサイズとする（指定があればそれに従う）
- 見出しごとに改ページしたい場合は CSS／オプションで制御し、本文には改ページ強制を埋め込まない
- ヘッダー・フッターを付ける場合は、ファイル名・ページ番号などの控えめな内容にとどめる

## 禁止事項

- Markdown には存在しない情報を「見栄えのために」追加する
- Mermaid 記法を画像化せず生のテキストのまま埋め込む（最終手段の場合は最終報告で明示する）
- 「Markdown から変換しました」などの前置きを本文に書く
- 変換できなかった要素を黙って捨てる（できなかった旨は必ず最終報告に書く）
