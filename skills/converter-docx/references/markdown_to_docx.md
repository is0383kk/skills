# Markdown → docx 変換リファレンス

編集済み Markdown を Word 文書（`.docx`）に戻すときの方針。
Markdown の論理構造（見出し階層・表・箇条書き・図）をそのまま Word のスタイルへ素直に対応付ける。

## 出力要件

- 出力形式は `.docx`
- 出力先は変換元 Markdown と同じディレクトリ。ファイル名は `XXXX.md` → `XXXX.docx`
- 出力先がすでに存在する場合は上書き可否をユーザーに確認する

## 入力の確認

呼び出し時に以下を確認する。

- 変換対象の Markdown ファイル（または Markdown を含むフォルダ）
- フォーマット（雛形 `.docx`）の指定有無
  - 指定がある場合: その雛形のスタイル定義（見出し・本文・表など）に従う
  - 指定がない場合: Markdown の構造に素直に従い、標準的な見出しスタイルを当てる

## 変換手段

- 組み込みの `docx` スキル（`Skill(docx)`）を使う
- 雛形が指定されている場合は、雛形の見出しスタイル名・本文スタイル名を尊重する

## 変換ルール

- 見出し階層は Word の Heading スタイルへ対応させる（`#` → Heading 1、`##` → Heading 2、…）
- Markdown の目次（リンク付き目次）は、Word の自動目次に置き換えてもよい。雛形に目次プレースホルダがあればそれを使う
- 表は Word のテーブルとして再現する。列見出し行はヘッダ行として扱う
- 箇条書き（`-`, `*`, `1.`）は Word の箇条書き／番号付きリストとして再現する
- コードブロックは等幅フォントの段落として再現する
- インラインの `（要確認: ...）` 注記は本文中にそのまま残す（レビューで気づけるようにするため）
- Mermaid 記法の図は `mermaid-js/mermaid-cli`（`mmdc`）等で画像化（PNG または SVG）してから Word に図として埋め込む
  - `mmdc -i input.mmd -o out.png` のように実行
  - 画像化に失敗する場合は、Mermaid のソースコードをそのままコードブロックとして残し、変換できなかった旨を最終報告に明記する
- HTML タグが Markdown 中にある場合は、装飾目的のものは無視し、意味のあるもの（注記・リンク等）はテキストとして残す

## 整形方針

- Markdown のセクション構造を Word の章節構造に対応させる
- ページ区切りや余白などの紙面整形は、雛形がない場合は最小限にとどめ、内容の論理構造を優先する
- 連続する空行や見た目調整のための装飾は持ち込まない
- 図表番号やキャプションが Markdown 上にある場合は、Word でもキャプションとして残す

## 禁止事項

- Markdown には存在しない情報を「見栄えのために」追加する
- 雛形のスタイル定義を勝手に書き換える
- Mermaid 記法を画像化せず生のテキストのまま埋め込む（最終手段の場合は最終報告で明示する）
- 「Markdown から変換しました」などの前置きを本文に書く
- 変換できなかった要素を黙って捨てる（できなかった旨は必ず最終報告に書く）
