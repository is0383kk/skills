# Markdown → xlsx 変換リファレンス

編集済み Markdown を Excel（`.xlsx` / `.xlsm`）の雛形（フォーマットファイル）へ流し込むときの方針。
Excel は雛形に強く依存することが多く、雛形の構造を尊重することを最優先とする。

## 想定される基本シナリオ

ユーザーから次のような形で指示が来るのが基本パターン。

```
{マークダウンファイル名} を Excel ファイルに変換してください。

フォーマットは
{フォーマットファイル名}
を使用してください。

Mermaid で記述されている図は「mermaid-js/mermaid-cli」を使用し画像化した上で
Excel ファイルに埋め込んでください。
```

このシナリオは以下の3つの要素を含む。

1. **入力 Markdown** が指定される
2. **フォーマット雛形 `.xlsx`** が指定される（雛形のシート構成・セル位置を維持して値だけ埋める）
3. **Mermaid 図は画像化して埋め込む**（テキストのまま貼らない）

入力 Markdown は指定されているがフォーマット雛形が指定されていない場合は、雛形を指定すべきかをユーザーに確認する。シートを新規作成してよいかも併せて確認する。

## 出力要件

- 出力形式は `.xlsx`（雛形が `.xlsm` の場合は `.xlsm`）
- 出力先は変換元 Markdown と同じディレクトリ。ファイル名は `XXXX.md` → `XXXX.xlsx`
- 雛形ファイル自体は**直接書き換えず**、コピーを取って書き込む
- 出力先がすでに存在する場合は上書き可否をユーザーに確認する

## 入力の確認

呼び出し時に以下を確認する。

- 変換対象の Markdown ファイル（または Markdown を含むフォルダ）
- フォーマット（雛形 `.xlsx` / `.xlsm`）の指定有無
  - 指定がある場合: 雛形のシート構成・項目・セル位置・データ検証ルールを尊重する
  - 指定がない場合: Markdown の構造を素直にシートへ起こすか、雛形を指定するようユーザーに促す

## 変換手段

- 組み込みの `xlsx` スキル（`Skill(xlsx)`）を使う
- 内部実装としては openpyxl を直接操作する経路でよい（`.xlsm` を扱う場合はマクロを保持するため `keep_vba=True` を指定する）

## 雛形のマッピング規約

雛形のセル構造を尊重するための基本ルール。

1. **シート構成**: 雛形のシート名・順序・存在を変更しない。Markdown 側のセクション（`#` シート名）を雛形のシート名に対応付けて値を流し込む
2. **項目名 → セル位置**: 雛形上の「項目名セル」（例: `A5: システム名`）の隣接セル（同じ行の値セル）に Markdown 側の値を書き込む
3. **複数行の自由記述**: 雛形に「説明欄」のような結合セル領域がある場合は、結合は維持したまま左上セルにテキストを書き込む（改行は `\n`）
4. **表データ**: 雛形に表のヘッダー行がある場合、ヘッダーの直下から1行ずつデータを書き込む。雛形の罫線・色は崩さない
5. **空欄項目**: Markdown 側で対応する記述がない項目は、雛形の空欄をそのまま残し、最終報告で対応漏れとして列挙する

雛形と Markdown の対応がはっきりしない箇所は、推測で書き込まずに**最終報告で確認事項として列挙**する。

## 変換ルール

- Markdown 表（`| ... | ... |`）は、対応する雛形の表領域に流し込む
- 箇条書きはセル内の改行付きテキストとして書き込む（雛形の項目欄が単一セルの場合）
- インラインの `（要確認: ...）` 注記はセルの値として残す（レビュアーがすぐ気づけるようにするため）
- 数式そのものを Markdown が示している場合（`=SUM(A1:A10)` のように）は、雛形の意図に合うときのみ数式として書き戻し、それ以外は値として書き込む

## Mermaid 図の埋め込み

Markdown 中の Mermaid コードブロック（```` ```mermaid ```` ）は、Excel の対応するセル領域に**画像として埋め込む**。

### 推奨手順

1. Markdown から Mermaid コードブロックを抽出して一時ファイルに書き出す（例: `temp/mermaid_001.mmd`）
2. `mermaid-js/mermaid-cli`（`mmdc`）で画像化する
   ```bash
   npx -p @mermaid-js/mermaid-cli mmdc -i temp/mermaid_001.mmd -o temp/mermaid_001.png
   ```
   - `mmdc` がインストールされていない場合は `npm install -g @mermaid-js/mermaid-cli` を案内するか、`npx -p` で都度実行する
   - 日本語フォントが必要な場合は、puppeteer の設定でフォントを指定する（環境依存のため、文字化けが起きた場合は最終報告で言及する）
3. openpyxl の `Image` で対象セル位置に画像を貼り付ける
   ```python
   from openpyxl.drawing.image import Image
   img = Image("temp/mermaid_001.png")
   ws.add_image(img, "B10")
   ```
4. 一時ファイル（`.mmd` / `.png`）は変換完了後に削除する

### 失敗時のフォールバック

- `mmdc` の実行に失敗する場合は、Mermaid のソースコードをそのままセルに（コードブロック相当の文字列として）書き込み、変換できなかった旨を最終報告に明記する
- 「画像化失敗を黙って捨てる」「テキストのまま埋めて何も言わない」のは禁止

## 整形方針

- 雛形のセル幅・行高・フォント・色・罫線を変更しない
- Markdown には存在しない情報を「見栄えのために」追加しない
- 雛形にないシート・行・列を勝手に追加しない（必要な場合はユーザー確認）

## 禁止事項

- Markdown には存在しない情報を「見栄えのために」追加する
- 雛形ファイル自体への直接上書き
- 雛形の構造（シート構成、セル位置、結合範囲）の改変
- Mermaid を画像化せず生のテキストのまま埋め込む（最終手段の場合は最終報告で明示する）
- 「Markdown から変換しました」などの前置きをセルに書く
- 変換できなかった要素を黙って捨てる（できなかった旨は必ず最終報告に書く）
