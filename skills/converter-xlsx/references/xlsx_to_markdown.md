# xlsx → Markdown 変換リファレンス

Excel 資料を AI 駆動開発で扱いやすい Markdown へ変換するときの方針。
Excel の見た目を再現するのではなく、文書に含まれる**情報の構造と内容**を Markdown で読みやすく表現することが目的。

## 出力要件

- 出力形式は Markdown（`.md`）
- シート単位でセクションを分割する
- 出力先は変換元ファイルと同じディレクトリ。ファイル名は `変換元ファイル名.md`（`XXXXX_XXXXX.xlsx` → `XXXXX_XXXXX.md`）
- 元のシート名を見出しとして記載する
- 表形式の情報は Markdown テーブルで表現する
- セクション構造が分かるように見出し（`#`, `##`, `###` …）を付ける
  - シート名を `#` 見出しとする

## 変換手段

- 組み込みの `xlsx` スキル（`Skill(xlsx)`）を使う

## 変換ルール

- 非表示シートは変換しない
- 非表示行・非表示列に含まれる内容は変換しない
- 空白セルのみの領域は出力しない
- セル結合、罫線、色、フォント、幅、高さなどの見た目情報は原則として持ち込まない
- 数式は原則として式そのものではなく、表示されている値を採用する
- 文書として意味のあるラベルや注記は失わない
- 備考、注釈、入力説明、注意書きなど、文書として意味のある文言は残す
- 画像、図形、Excel 固有の装飾説明は、内容理解に必須でない限り出力しない
- 図・作業フローなど Mermaid で表現できるものは Mermaid 記法を使う
- 連番や採番列が Excel の数式で自動生成されているだけの場合は、その仕組みの説明を書かない
- 「この列は Excel では自動計算」などの変換メモは出力しない
- Markdown 化そのものに集中し、変換者としてのコメントは一切付けない

## 整形方針

- Markdown を読んだ人が、Excel を開かなくても内容を把握できるようにする
- 可読性を優先し、不要に巨大な1つの表にまとめない
- 項目名・説明・値・条件・備考の対応関係が崩れないようにする
- テンプレートの空欄項目は、意味がある場合のみ項目名を残して空欄と分かるように表現する
- 同じ意味の見出しや表が重複する場合は、不要な重複を避ける
- 日本語の自然な見出し名を用い、機械的にセル番地や座標を出力しない

## 禁止事項

- 非表示部分の出力
- Excel の見た目やレイアウト再現を目的とした記述
- 変換ルールそのものや、Excel/Markdown の操作説明の出力
- 「No.列は Excel 上では `=ROW()-1` で自動採番」などの補足コメントの出力
- 変換処理に関する言い訳や補足コメント
- 「以下は変換結果です」などの前置き
- 不要なコードブロックの使用
