# converter-xlsx

Excelファイル（`.xlsx` / `.xlsm` / `.xls`）と Markdown の双方向変換を担う。

- 既存の Excel 資料を AI 駆動開発で扱いやすい Markdown に変換する（**正方向**）
- 編集済み Markdown を Excel の雛形（フォーマットファイル）に流し込む（**逆方向**）

組み込みの `xlsx` スキル（`Skill(xlsx)`）を土台に使い、対象ファイルや指示の文脈から方向を判断して動く。

## 想定する利用シーン

このスキルは特定のプロセス標準に縛られない**汎用ドキュメント変換スキル**として使える。具体的には次のような場面を想定する。

- 業務リスト・チェックリスト・台帳を Markdown で整理し、AI に読み解かせる
- 顧客や他部署から受領した Excel 資料を取り込み、編集後にもとの形式に戻す
- 設計書・仕様書・報告書など、雛形（フォーマットファイル）が決まっている文書を、Markdown と Excel の間で往復させる
- 過去の Excel 資産を、検索・差分管理しやすい Markdown 資産へ転換する

Excel は Office 文書のなかでも雛形に強く依存することが多い。逆方向ではフォーマット雛形を指定するワークフローが基本となる。

## 起動条件と方向の判定

呼び出された文脈から、まず「どちらの方向か」を決める。判定は次の優先順で行う。

1. ユーザーが明示している場合はそれに従う
2. 入力ファイルが `.xlsx` / `.xlsm` / `.xls` のみなら **Markdown化（正方向）**
3. 入力ファイルが `.md` のみなら **Excel化（逆方向）**
4. 両方含まれている場合（`.md` と雛形 `.xlsx` の組み合わせなど）は、ユーザーへ意図を確認する

判別が付かないときは推測で進めず、対象ファイル・出力先・方向をユーザーに確認する。

## 共通方針

- 出力先は原則として変換元と同じディレクトリ。ファイル名は拡張子だけを差し替える（`XXXX.xlsx` ⇔ `XXXX.md`）
- ただし**逆方向**で雛形を別途指定された場合、出力先は雛形の隣ではなく Markdown と同じディレクトリに置く
- 出力先がすでに存在する場合は、上書きしてよいかをユーザーに確認する
- Excel の見た目（罫線・色・フォント・列幅・結合）の再現を目的にしない。情報の構造と内容を双方向で保つことを優先する
- 「以下は変換結果です」のような前置きや、変換ルールそのものの説明、変換処理の言い訳は本文に書かない
- 不要なコードブロックで全体を囲わない

## Step 1: 方向に応じて参照ドキュメントを読む

- **Markdown化（xlsx → md）** の場合は `references/xlsx_to_markdown.md` を読む
- **Excel化（md → xlsx）** の場合は `references/markdown_to_xlsx.md` を読む
  - フォーマット（雛形 `.xlsx`）指定が前提のフロー、Mermaid 図を `mermaid-js/mermaid-cli` で画像化して埋め込む手順も同ファイルに記載

各リファレンスには、変換ルール・整形方針・禁止事項・推奨フローがまとまっている。SKILL.md 本体には共通事項のみを置き、形式特有の細部はリファレンス側に寄せている。

## Step 2: 入出力の確認

- 変換対象（ファイルパス／フォルダパス）が指定されていることを確認する
- フォルダ指定の場合は、配下の対象拡張子をすべて変換する
- **逆方向**では、フォーマット（雛形 `.xlsx`）が指定されているかを確認する
  - 指定されていれば、その雛形のシート構成・項目・セル位置・データ検証ルールを尊重する
  - 指定されていない場合は、Markdown の構造を素直にシートへ起こすか、雛形を指定するようユーザーに促す

## Step 3: 変換の実行

- 変換中は、対象ファイル名と方向を1行で報告する程度にとどめる
- 文字コードは UTF-8、改行コードは LF を基本としつつ、既存ファイルがある場合はそれを尊重する
- 図・作業フローなど Mermaid で表現できるものは、正方向では Mermaid 化、逆方向では `mermaid-js/mermaid-cli`（`mmdc`）で画像化してから Excel に画像として埋め込む

## Step 4: 結果報告

- 入力 → 出力のパスを列挙する
- 推測で補った箇所がある場合は本文中に `（要確認: 理由）` をインラインで残し、報告でも触れる
- 変換できなかった要素（読み取れない図、画像化に失敗した Mermaid、雛形の項目に対応するデータが Markdown 側で見つからなかった項目など）があれば、その旨を簡潔に伝える

## 禁止事項

- 非表示シート／非表示行・列の出力
- Excel の見た目やレイアウト再現を目的とした記述
- 変換ルールそのものや、Excel/Markdown の操作説明（数式仕組みの解説を含む）の出力
- 推測による無理な補完（特に逆方向で雛形のセル位置を勝手に変える）
- 「以下は変換結果です」などの前置き
