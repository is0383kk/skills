# Markdown → pptx 変換リファレンス

編集済み Markdown を PowerPoint（`.pptx`）に戻すときの方針。
Markdown の構造（見出し階層・箇条書き・表・図）を素直にスライドへ対応付ける。

## 出力要件

- 出力形式は `.pptx`
- 出力先は変換元 Markdown と同じディレクトリ。ファイル名は `XXXX.md` → `XXXX.pptx`
- 出力先がすでに存在する場合は上書き可否をユーザーに確認する

## 入力の確認

呼び出し時に以下を確認する。

- 変換対象の Markdown ファイル（または Markdown を含むフォルダ）
- フォーマット（雛形 `.pptx`）の指定有無
  - 指定がある場合: 雛形のスライドマスター・レイアウト・配色・フォントを尊重する
  - 指定がない場合: 標準的なテンプレートで生成する（タイトル + コンテンツのレイアウトを基本とする）

## 変換手段

- 組み込みの `pptx` スキル（`Skill(pptx)`）を使う
- 内部実装としては python-pptx を直接操作する経路でよい

## スライド分割の規約

Markdown のどこで「スライド」が切れるかを以下のルールで決める。

- 第1階層の `#` 見出し: プレゼン全体のタイトル → 表紙スライド
- 第2階層の `##` 見出し: 1スライドの単位 → タイトル付きコンテンツスライド
- 第3階層以降の `###`〜: スライド内の小見出しとして扱う（箇条書きや段落の見出しに）
- Markdown 内に明示的な `---`（水平線）がある場合は、そこでスライドを切ってもよい

判別が難しい場合（H2 が無い、全体が長い 1 セクション、など）は、ユーザーに分割方針を確認する。

## 変換ルール

- 表は PowerPoint のテーブルとして再現する。列見出し行はヘッダ行扱い
- 箇条書きは PowerPoint の箇条書きとして再現する。階層はインデント／レベルで表現
- スライド末尾の `**ノート:** ...` セクションは、スピーカーノートとして登録する
- インラインの `（要確認: ...）` 注記は本文中に残し、必要ならスピーカーノートにも控える
- Mermaid 記法の図は `mermaid-js/mermaid-cli`（`mmdc`）等で画像化（PNG/SVG）してからスライドに図として配置する
  - `mmdc -i input.mmd -o out.png` のように実行
  - 画像化に失敗する場合は、Mermaid のソースをテキストブロックとして残し、変換できなかった旨を最終報告に明記する
- コードブロックは等幅フォントのテキストボックスとして再現する

## 整形方針

- スライド1枚に詰め込みすぎない。情報量が多い場合はスライドを分割する判断をしてよい（その旨を最終報告に書く）
- 表が大きすぎる場合は、見出し行＋要約だけスライドに置き、詳細は付録扱いにする選択肢もある（ユーザー確認）
- 装飾は雛形に従い、Markdown 上にない色／フォントを勝手に追加しない

## 禁止事項

- Markdown には存在しない情報を「見栄えのために」追加する
- 雛形のスライドマスター／レイアウト定義を勝手に書き換える
- Mermaid 記法を画像化せず生のテキストのまま埋め込む（最終手段の場合は最終報告で明示する）
- アニメーションやトランジションを勝手に追加する
- 「Markdown から変換しました」などの前置きをスライドに書く
- 変換できなかった要素を黙って捨てる（できなかった旨は必ず最終報告に書く）
