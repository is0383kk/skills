# AIエージェント向け資産の品質レビュー

AIエージェントが参照・使用する資産を、対象種別に応じた品質チェックリストの観点でレビューするスキル。
`references` 配下の**対象チェックリストをコピーして判定を記入したマークダウン**を成果物として出力する。

## 対象チェックリストの選択

対象種別によって参照する対象チェックリストを切り替える。

| 対象種別                                                                                                      | 対象チェックリスト                                             |
| ------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| スキル（`.{agents/claude/codex/github/copilot}/skills/スキルフォルダ/` 配下一式）                             | `references/エージェントスキルの品質チェックリスト.md`         |
| その他（プロンプト／仕様書／ガイドライン／`AGENTS.md（CLAUDE.md/copilot-instructions.md）`／スクリプト など） | `references/AIエージェント向け汎用資産の品質チェックリスト.md` |

## ワークフロー

複数ステップにわたるため下記の作業チェックリストに従いタスク管理する。

```
- [ ] 1. レビュー対象のパスと対象種別・目的・利用場面・対象モデル/実行環境を確認した
- [ ] 2. 対象種別から参照する対象チェックリストを選び、読んで観点を把握した
- [ ] 3. 対象資産の内容を読み、必要に応じて行数・用語・パス表記などを機械的に確認した
- [ ] 4. 各チェック項目について 満たす / △ / ✕ / N/A を判定した
- [ ] 5. 対象チェックリストをコピーして判定を記入した出力マークダウンを作成し、元チェックリストと構造が一致することを検証した
- [ ] 6. 重要度順に所見を要約し、未検証項目とともに報告した
```

### 1. チェック対象の確認

レビュー対象のパスと、次の文脈を確認する。
不明な場合は推測で進めず、ユーザーに確認する。

- 対象種別（プロンプト／仕様書／ガイドライン／スキル／スクリプト／`AGENTS.md（CLAUDE.md／copilot-instructions.md）` など）
- 目的・主な利用場面・想定利用者や対象モデル・実行環境

対象種別は対象チェックリストの選択と、各チェック項目の「適用対象」の判断に使う。
**スキルの場合は、`SKILL.md` だけでなくスキルフォルダ全体（`references/`、`assets/`、`scripts/`、その他関連ファイル）を対象とする。**

### 2. 対象チェックリストの選択と観点の把握

「対象チェックリストの選択」に従い対象種別に対応する対象チェックリストを選び、それを読む。
冒頭の「判定記入項目」「判定の定義」と、各セクションのチェック項目・良い例が判定の基準になる。
スキルを対象とする場合は、汎用観点（1〜6）に加えスキル固有観点（7〜10）も対象になる。

### 3. 機械的チェック

客観的に判定できる項目は目視推測に頼らず、決定論的な処理は `scripts/mechanical_check.py` を**実行**して、その結果を根拠に使う（AIの判断と機械的処理を分離する）。

依存：Python 3.8 以上（標準ライブラリのみ。追加インストール不要）。

`python scripts/mechanical_check.py <対象パス>` を実行すると、対象内の Markdown／テキストについて次を機械的に出力する。

- 記述量・目次要否 → ファイル別の行数（100 行を超えるファイルを明示）
- パス表記 → バックスラッシュ（`\`）を含む行
- 数値・閾値 → 数値リテラルを含む行

用語の統一（揺れやすい語の混在）は対象ごとに語彙が異なるため、確認したい語をカンマ区切りで渡して全文検索する。

```
python scripts/mechanical_check.py <対象パス> --terms 取得,抽出,取り出す
```

### 4. 非機械的チェック

チェックリストの各項目に対し、判定基準と対象資産を照合して次のいずれかを判断する。

| 判定               | 意味                               | 出力での扱い                                                 |
| ------------------ | ---------------------------------- | ------------------------------------------------------------ |
| 満たす（修正不要） | 判定基準を満たしている             | チェックボックスを `[x]` にし、追加記入はしない              |
| `△`                | 満たしているが修正推奨             | `[ ]` のまま、項目直下に「判定記入項目」ブロックを追加       |
| `✕`                | 満たしておらず修正必要             | `[ ]` のまま、項目直下に「判定記入項目」ブロックを追加       |
| `N/A`              | 対象種別・目的・環境から適用対象外 | `[ ]` のまま、項目直下にブロックを追加し `適用外理由` を記入 |

`【重要】` 付きの項目は原則として満たす必要がある。満たせない場合は理由・影響・代替策を根拠に残す。
「適用対象外だから確認しない」という目的で `N/A` を使わない。
判定基準を満たすためだけに対象資産の本来の目的を変えない。

### 5. 出力マークダウンの作成と検証

出力ファイルはプロジェクト直下に出力する。
対象が分かる具体名にする（例：対象がスキル `my-skill` なら`./my-skill-品質レビュー-YYYY-MM-DD.md`）。

選択した**対象チェックリスト**を**そのままコピーし、フォーマットを変えずに**出力用マークダウンを作る。
編集してよいのは次の 2 点だけで、見出し・表・目次・「判定記入項目」の定義などの構造は元のまま保つ。

1. 各チェック項目のチェックボックス状態（満たす場合のみ `[x]`）
2. `△` / `✕` / `N/A` と判定した項目の**直下**に、下記の「判定記入項目」ブロックを追加する

**出力例（元の対象チェックリスト構造を保ったまま、該当項目の直下にブロックを追加）**

```
- [x] **【重要】記述量が適切である**：主要指示は短く保ち、長くなったら分割する（後述）
  - 良い例：本文は要点だけに絞り、200 行を超えるデプロイ手順の詳細は …

- [ ] **【重要】適用条件を明示する**：「何をする資産か」だけでなく、「いつ使うか」…
  - 良い例：「PDF を生成するときに使う。CSV や Excel を出力するときは使わない」…

  | 項目 | 内容 |
  |---|---|
  | 判定 | ✕ |
  | 問題箇所 | SKILL.md |
  | 根拠 | SKILL.md に「何をするか」はあるが「いつ使わないか」の記載がない（1〜20行目） |
  | 改善内容 | description に「CSV/Excel 出力時は xlsx スキルを使う」等の非適用条件を追記 |
  | 適用外理由 | － |
```

#### 出力後の検証（フィードバックループ）

出力後、生成したマークダウンが**元の対象チェックリストと構造的に一致している**ことを機械的に照合する（AI の記憶に頼らず、元ファイルと突き合わせる）。

- 見出し・表・目次・チェック項目の**文言・数・順序**が元チェックリストと一致しているか（変更してよいのはチェックボックス状態と、`△` / `✕` / `N/A` 項目直下に追加する「判定記入項目」ブロックだけ）
- 元の文言を書き換えたり、項目を削除・並べ替えていないか

不一致があれば修正し、再度照合する。
**同じ不一致が 2 回連続で解消できない場合は、原因（元ファイルのコピー漏れ・読み違いなど）を報告して停止する。**

### 6. 所見の報告

出力ファイルのパスに加え、`✕`（必須の未達を優先）→ `△` の順で主要な所見を要約する。
機械的に確認できなかった項目（対象モデルでの実行評価など）は「未検証」として理由とともに明示する。
「問題なし」だけで終えず、判断の根拠を簡潔に添える。

## 例外時の行動

- **対象ファイルが存在しない／パスが曖昧** → 内容を推測せず処理を停止し、正しいパスをユーザーに確認する。
- **対象種別が判断できない** → 推測で「適用対象」を決めず、ユーザーに対象種別を確認する。
- **対象チェックリストが読めない** → 該当する対象チェックリスト（`references/` 配下）の欠落を報告して停止する。
- **対象が巨大で全項目を確認しきれない** → レビュー対象範囲を先に合意し、範囲外は出力に「対象外」と明示する。

## 完了条件

次をすべて満たしたらレビュー完了とする。

- 全チェック項目について 満たす / △ / ✕ / N/A のいずれかを判断した（未確認項目は「未検証」と理由を明記）
- 対象チェックリストの構造を変えずにコピーし、`△` / `✕` / `N/A` 項目に判定記入項目ブロックを追加した出力マークダウンを保存した
- 生成した出力マークダウンが元の対象チェックリストと構造的に一致することを検証した（不一致は修正済み、または解消できない場合は原因を報告済み）
- 出力ファイルのパスと、重要度順の所見・未検証項目を報告した
